MCP 到底是什么

把「它本质上是个协议，配了之后 Agent 能访问一些资源」这句模糊的印象，换成一段你能复述给别人的准确表述。

第 1 册 · 基于 MCP 规范 2026-07-28
本册要解决的困惑

这一册从三个问题开始：MCP 要解决什么问题、处于应用的哪一层、与工具调用有什么关系。读完后，可以用一条完整的调用链解释 MCP 的作用与边界。

1它要解决的问题

先不谈 MCP 本身，先看它在没有的时候，世界是什么样。

考虑一个常见的集成场景：

  • 三个 AI 应用：Claude Desktop、VS Code 里的编程助手、你自己写的一个 Agent 程序。
  • 三个数据源或能力：你本机的文件系统、公司的 Postgres 数据库、GitHub 的 issue。

如果没有统一标准，会发生什么？每让「某一个 AI 应用」访问「某一个数据源」，你就要为这个组合单独写一份对接代码 —— 怎么连、怎么认证、怎么把数据源的接口翻译成模型能用的形式、返回怎么解析。这些代码彼此不能复用。

三个应用配三个数据源，就是 3 × 3 = 9 份对接代码。如果应用变成 4 个、数据源变成 5 个，就是 4 × 5 = 20 份。数量是相乘的，所以叫 M×N 问题。

MCP 的做法是把这件事拆成两个方向：AI 应用这一侧统一实现「会讲 MCP」，数据源那一侧也统一实现「会讲 MCP」。双方都对着同一份规定说话，就不需要两两配对了。对接代码从 M × N 变成 M + N。三个应用配三个数据源，从 9 份变成 6 份；4 和 5 的情况下从 20 份变成 9 份。

这里的关键

MCP 并没有让任何一方的功能变多。它唯一改变的是对接成本的结构：从乘法变成加法。这也是为什么理解 MCP 时，「它提供什么功能」是个错误的问题，「它规定了什么」才是对的问题。

2一条准确的定义

下面这句话可以直接背下来：

定义

MCP（Model Context Protocol，模型上下文协议）是一套开放的、基于 JSON-RPC 2.0 的标准协议，用来规定「AI 应用」与「外部能力提供方」之间如何进行能力发现、请求调用和结果返回。

这句话里每个词都有信息量，逐个拆开：

「开放的」

它不属于某一家公司。MCP 由 Anthropic 在 2024 年 11 月提出，2025 年 12 月捐给了 Linux 基金会下的 Agentic AI Foundation。现在 Anthropic、OpenAI、Google、Microsoft 的产品和 SDK 都支持它。这一点决定了它和「某家厂商的私有插件机制」是两类东西。

「基于 JSON-RPC 2.0」

消息的格式不是自己发明的，用的是已有的 JSON-RPC 2.0 规范。这意味着：每一条 MCP 消息就是一个 JSON 对象，带固定的几个字段（jsonrpc、method、id、params 等）。你甚至不需要任何 SDK，手工拼 JSON 也能说 MCP。第 3 册会把真实报文摊开看。

「标准协议」

协议规定的是「怎么对话」，不是「提供什么」。规范文档里没有任何一个具体的工具、任何一个具体的数据库。它只规定：发现能力用哪个方法、调用工具用哪个方法、返回值应该长什么样。

「AI 应用」与「外部能力提供方」

这是协议的两端。MCP 规范里给它们起的正式名字分别是 Host（主机，即 AI 应用）和 Server（服务器，即能力提供方）。中间还有第三个角色 Client。下一节先认识这三个名字。

3MCP 不是什么

MCP 经常被用来指代不同层次的东西。先划清边界，再看具体用法，会更容易理解。下面是六条常见的误解。

误解 1「MCP 是一个 AI 模型 / 一种 AI 技术。」
事实MCP 里不包含任何模型，不做推理，不生成文本。它是应用与外部世界之间的对话规则。换掉背后的模型，MCP 一点不用变。
误解 2「MCP 是一个框架 / 一个代码库。」
事实MCP 是一份规范（specification），本质是一份规定消息格式的文档。你听到的「Python SDK」「Go SDK」是这份规范的实现，是别人写好方便你用的库，不是规范本身。不用 SDK 照样能写出符合 MCP 的程序。
误解 3「MCP 是一种网络传输协议。」
事实MCP 定义在传输层之上。它不关心字节怎么走 —— 可以用进程的标准输入输出（stdio）传，也可以用 HTTP 传。传输方式只是「信封」，MCP 规定的是「信的内容」。这是两个独立的层，第 2 册会画出来。
误解 4「MCP 是一个工具集合 / 插件市场。」
事实规范里一个具体工具都没有。你听说过的 server-filesystem、server-github 是别人按照 MCP 写出来的程序，属于「Server」这个角色的具体实现，不是 MCP 的组成部分。MCP 是插座标准，不是电器清单。
误解 5「MCP 是 Anthropic / Claude 专属的。」
事实它已经捐给 Linux 基金会，OpenAI、Google、Microsoft 都有支持。它是中立标准，不属于任何一家。
误解 6「MCP 就是『AI 单方面调用工具』。」
事实不完全是。MCP 是双向的能力声明：Server 可以暴露工具给 AI 用；同时 Client 也可以向 Server 声明自己的能力（例如「我可以向用户提问」）。这是它区别于普通 REST API 的一个要点，第 2 册会讲清楚双向分别是什么。

4三个角色，先记住名字

后面每一册都会反复用这三个词，所以这里先给最小的定义，第 2 册再展开。

角色是什么典型例子
Host（主机） 那个 AI 应用本身 —— 用户直接交互的东西。它负责管理下面所有连接。 Claude Desktop、VS Code、Cursor、你自己写的 Agent 程序
Client（客户端） Host 内部的一个组件。每连接一个 Server，Host 就创建一个对应的 Client。它负责维持这条连接、发消息、收结果。 不是独立程序，是 Host 里的一个对象
Server（服务器） 提供能力的程序。它对外声明「我能做什么」，等待被调用。 filesystem server、github server、你按第 6/7 册写出来的那个
最容易记错的一点

Host 和 Client 都在同一侧（AI 应用这一侧），不是两个阵营。一个 Host 内部可以有多个 Client，每个 Client 管一条到某个 Server 的连接。所以是「一 Host → 多 Client → 多 Server」的结构。

5为什么「到处都在设计 MCP」

不同项目都可能声称自己在「做 MCP」，但具体工作并不相同：同一个词，在不同语境下可能指协议、客户端、服务端或配套工具。

因为 MCP 定义的是「角色」，而每个角色都可以由不同的人、在不同的地方去实现。所有这些工作都可以被笼统地叫做「搞 MCP」。下表把常见的说法翻译一遍：

你听到的说法实际在做什么对应角色 / 层次
「我给 Cursor 配了个 MCP」 在 Cursor 的配置文件里加了一条 server 记录，让它启动 / 连接某个 server 在使用 Host 的配置能力
「我写了个 MCP server」 按规范实现一个对外提供能力的程序 实现 Server
「我们的产品支持 MCP」 产品要么能当 Host（连别人的 server），要么自己就是 Server（被别人连） 实现 Host 或 Server
「我用了 MCP SDK」 用官方 / 第三方的库来写 client 或 server，省去手拼 JSON 用 SDK 去实现某个角色
「我们在做 MCP 网关」 在企业里统一转发、鉴权、限流、审计所有 MCP 流量 中间层（既不是 Host 也不是 Server）
「MCP 出了个新扩展」 在核心协议之外，加一层可选能力（如长任务、内联 UI） 扩展（核心协议之上的可选模块）

所以当你再听到「某某设计了一个 MCP」时，只需要问一句：它是在实现 Host、实现 Server、还是做中间层？ 问出这一句，模糊感基本就消掉了。第 4 册会把这张地图完整铺开。

6一句话总结

第 1 册 · 一句话总结

MCP 是一份规定「AI 应用（Host）与能力提供方（Server）之间如何互相发现和调用」的开放协议，它把对接成本从 M×N 降成 M+N；它本身不含模型、不含工具、不含传输方式，只规定对话的格式；实现它的人分三种角色 —— Host、Client、Server，而「到处都在设计 MCP」的说法，只是在说不同的人在实现不同的角色。
