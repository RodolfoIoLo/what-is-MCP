Python 完整实现

从零写一个能查 SQLite 的 MCP server，再写 client，最后把工具接进 LLM 跑通完整循环。代码完整、可运行，并且解释为什么这样组织。

第 6 册 · Python SDK v2 · 基于 MCP 规范 2026-07-28
本册目标

前五册是「看懂」，这一册是「写出」。你会得到一个包含四个文件的小项目：造数据的脚本、MCP server、MCP client、以及一个把 MCP 工具交给模型使用的 agent。三个原语（工具 / 资源 / 提示）全部用上。

1要做的东西

目标是一个「SQLite 浏览器」server。SQLite 不需要另外部署数据库服务，适合本地练习；表结构、查询和分析步骤也正好可以分别用资源、工具和提示模板来表达。

暴露的东西类型作用
list_tables工具列出所有表名
query工具执行一条只读 SQL，返回结构化结果
schema://tables资源完整的建表语句，供模型写查询前参考
table://{name}/sample资源模板某张表的前 5 行示例数据
write_analysis_query提示模板把一句自然语言问题变成「先看 schema 再写 SQL」的指令

2环境与依赖

本章使用 mcp[cli]==2.3.0 和 openai==3.31.0；后者只给第 8 节的 agent 使用。如果已经下载仓库，进入 mcp-demo-py 后执行 uv sync 即可安装依赖。下面是从空目录手动搭建的两种方式，任选一种。

走方式二的话，把 uv run 去掉、直接写 X 就行 —— 前提是当前终端已经激活了虚拟环境（提示符前面出现 (.venv)）。每开一个新终端都要重新激活一次，否则 python 找不到刚装好的包。

uv: command not found

uv 默认装在 ~/.local/bin（Windows 是 %USERPROFILE%\.local\bin），这个目录不一定会被加进 PATH。装了但敲不出来就是这个问题 —— 要么加进 PATH，要么直接用方式二。

关于版本

本教程使用 Python 3.11 或更新版本。本册代码针对 SDK v2（from mcp.server import MCPServer）。如果你在旧教程里看到 from mcp.server.fastmcp import FastMCP，那是 v1 的写法，v2 已经改了。

3代码怎么组织

mcp-demo-py/ ├── seed.py # 造一个 demo.db，只跑一次 ├── server.py # MCP server：对外暴露工具 / 资源 / 提示 ├── client.py # MCP client：直接调用 server，看返回什么 ├── agent.py # 把 server 的工具交给模型，让模型决定调什么 ├── demo.db # SQLite 数据库文件（由 seed.py 生成） ├── pyproject.toml # 方式一（uv）生成 └── requirements.txt # 方式二（pip）可选，用来固定版本

为什么分成这四个文件？每一条都对应一个真实的边界：

  • seed.py 和 server.py 分开：造数据是一次性的，读数据是长期的。混在一起会导致每次启动 server 都重建数据库。真实项目里，数据初始化也总是独立的一步。
  • server.py 和 client.py 分开：这两者运行在不同的进程里。server 是被启动的那一方，client 是发起连接的那一方。写成两个文件，能让你亲眼看到「它们之间只有 MCP 消息这一条通路」，没有别的耦合。
  • client.py 和 agent.py 分开：这两者都是「连接方」，但层次不同。client.py 是人决定调哪个工具（写死调用），agent.py 是模型决定调哪个工具。把它们分开，能看清「Host 到底做了哪些事」。

4seed.py：造一个真实的数据库

Python · seed.py 
import sqlite3
from pathlib import Path

DB_PATH = Path(__file__).parent / "demo.db"

SCHEMA = """
DROP TABLE IF EXISTS orders;
DROP TABLE IF EXISTS customers;

CREATE TABLE customers (
    id     INTEGER PRIMARY KEY,
    name   TEXT NOT NULL,
    city   TEXT NOT NULL,
    joined TEXT NOT NULL
);

CREATE TABLE orders (
    id          INTEGER PRIMARY KEY,
    customer_id INTEGER NOT NULL REFERENCES customers(id),
    amount      REAL NOT NULL,
    created_at  TEXT NOT NULL
);
"""

CUSTOMERS = [
    (1, "张伟", "武汉", "2024-03-11"),
    (2, "李娜", "上海", "2024-07-02"),
    (3, "王强", "武汉", "2025-01-19"),
    (4, "赵敏", "北京", "2025-05-30"),
]

ORDERS = [
    (1, 1, 128.50, "2026-08-03"),
    (2, 1, 340.00, "2026-08-19"),
    (3, 2,  99.90, "2026-09-01"),
    (4, 3, 520.00, "2026-09-12"),
    (5, 4,  75.20, "2026-09-28"),
    (6, 2, 210.00, "2026-10-02"),
]


def main() -> None:
    conn = sqlite3.connect(DB_PATH)
    conn.executescript(SCHEMA)
    conn.executemany("INSERT INTO customers VALUES (?, ?, ?, ?)", CUSTOMERS)
    conn.executemany("INSERT INTO orders VALUES (?, ?, ?, ?)", ORDERS)
    conn.commit()
    conn.close()
    print(f"已生成 {DB_PATH}")


if __name__ == "__main__":
    main()

5server.py：写 MCP server

下面先给完整代码，再逐段拆开讲。建议你先整体看一遍结构，再读讲解。

Python · server.py 
import sqlite3
from pathlib import Path

from pydantic import BaseModel

from mcp.server import MCPServer
from mcp.server.mcpserver.exceptions import ToolError

DB_PATH = Path(__file__).parent / "demo.db"

mcp = MCPServer(
    name="sqlite-explorer",
    instructions=(
        "查询本地 SQLite 数据库。写 SQL 之前先读取 schema://tables 资源，"
        "确认表名和字段名，不要凭猜测写查询。"
    ),
)

# MCPServer: name 标识服务；instructions 提供使用建议。
# Host 需要读取并使用这些说明；它们不会自动进入模型的对话。


def connect_readonly() -> sqlite3.Connection:
    """以只读方式打开已有数据库；文件不存在时不会悄悄创建空库。"""
    conn = sqlite3.connect(DB_PATH.resolve().as_uri() + "?mode=ro", uri=True)
    conn.execute("PRAGMA query_only = ON")
    return conn


# 工具函数的四条约定：
# 1. 参数与类型注解 -> inputSchema
# 2. docstring -> 工具描述
# 3. 函数名 -> 默认工具名
# 4. 返回注解 -> outputSchema（能生成结构时）
@mcp.tool(title="列出所有表")
def list_tables() -> list[str]:
    """列出数据库中所有表名。"""
    conn = connect_readonly()
    try:
        rows = conn.execute(
            "SELECT name FROM sqlite_master WHERE type = 'table' ORDER BY name"
        ).fetchall()
        return [row[0] for row in rows]
    finally:
        conn.close()


class QueryResult(BaseModel):
    """一次查询的结果；最多返回 max_rows 行。"""

    columns: list[str]
    rows: list[list]
    row_count: int
    truncated: bool


# BaseModel 用一个类描述结果的结构，也会校验构造它时传入的数据。
# 这里的模型是“数据模型”，与生成回答的 LLM 不是同一件事。
@mcp.tool(title="执行只读查询")
def query(sql: str, max_rows: int = 100) -> QueryResult:
    """执行 SELECT 或 WITH 查询。max_rows 为 1–1000，truncated 表示还有未返回的行。"""
    if not sql.strip().lower().startswith(("select", "with")):
        raise ToolError("只接受 SELECT / WITH 查询。")
    if not 1 <= max_rows <= 1000:
        raise ToolError("max_rows 必须在 1 到 1000 之间。")

    # 前缀检查用于给出友好提示；真正的只读限制由数据库连接负责。
    try:
        conn = connect_readonly()
        try:
            cur = conn.execute(sql)
            if cur.description is None:
                raise ToolError("这条语句没有返回结果集。")
            columns = [column[0] for column in cur.description]
            fetched = cur.fetchmany(max_rows + 1)
        finally:
            conn.close()
    except sqlite3.Error as exc:
        raise ToolError(f"SQL 执行失败：{exc}") from exc

    rows = [list(row) for row in fetched[:max_rows]]
    return QueryResult(
        columns=columns,
        rows=rows,
        row_count=len(rows),
        truncated=len(fetched) > max_rows,
    )


@mcp.resource("schema://tables")
def schema_overview() -> str:
    """数据库的完整建表语句，供写查询前参考。"""
    conn = connect_readonly()
    try:
        tables = conn.execute(
            "SELECT name, sql FROM sqlite_master "
            "WHERE type = 'table' ORDER BY name"
        ).fetchall()
        return "\n\n".join(f"-- {name}\n{ddl}" for name, ddl in tables)
    finally:
        conn.close()


@mcp.resource("table://{name}/sample")
def table_sample(name: str) -> str:
    """某张表的前 5 行示例数据。"""
    conn = connect_readonly()
    try:
        exists = conn.execute(
            "SELECT 1 FROM sqlite_master WHERE type = 'table' AND name = ?",
            (name,),
        ).fetchone()
        if exists is None:
            raise ValueError(f"表不存在：{name}")
        # SQL 的 ? 占位符不能代替表名；校验存在后还要转义标识符。
        quoted_name = '"' + name.replace('"', '""') + '"'
        cur = conn.execute(f"SELECT * FROM {quoted_name} LIMIT 5")
        columns = [column[0] for column in cur.description]
        rows = cur.fetchall()
    finally:
        conn.close()

    lines = [" | ".join(columns), "-" * 32]
    lines += [" | ".join(str(value) for value in row) for row in rows]
    return "\n".join(lines)


@mcp.prompt(title="写一条分析查询")
def write_analysis_query(question: str) -> str:
    """把分析问题组织成一份查询步骤；调用它本身不会执行 SQL。"""
    return (
        "请根据下面的问题分析 SQLite 数据库。\n"
        f"问题：{question}\n\n"
        "1. 使用 Host 提供的 schema://tables 表结构，确认表名和字段名；\n"
        "2. 编写只读 SELECT；\n"
        "3. 用 query 工具执行；\n"
        "4. 根据实际结果用中文回答；truncated 为 true 时说明结果被截断。"
    )


if __name__ == "__main__":
    mcp.run()

基础用法 ↔ 它实现了什么

这个 server 只用了五处「MCPServer 的用法」。先看它们各自换来了什么，再往下逐段读代码。

写下的代码注册成了什么对客户端意味着
MCPServer("sqlite-explorer", instructions=...)server 的身份 + 给模型的说明连上后第一眼看到的名字和 instructions
@mcp.tool()一个工具客户端按工具名调用；模型可以提出调用请求，由 Host 执行
@mcp.resource("uri")一个资源客户端可以按 URI 读取你的数据
@mcp.prompt()一个提示模板用户可以在界面上选它、填参数、拿到一段指令
mcp.run()启动服务进程开始监听，等客户端发消息进来

三者最容易混的是「谁在用」：工具接受名字和参数，资源按 URI 读取，提示模板生成消息。模型可以选择工具，Host 负责执行调用；资源和模板也需要 Host 主动接入。（每一条链路具体走哪个方法名、返回什么，Python SDK 手册里有逐条对照。）

逐段讲解

① 创建 server

Python 
mcp = MCPServer(
    "sqlite-explorer",
    instructions="查询本地 SQLite 数据库。写 SQL 之前先读取 schema://tables ...",
)

MCPServer("名字", instructions="...") 创建 server 对象，客户端可以取得服务身份信息。此时只是准备好服务，还没有执行查询；直到运行服务并收到调用，工具函数才会执行。

instructions 提供整个服务的使用建议，工具的 docstring 则解释各自的用途。Host 需要读取这些信息并传给模型；它们不会自动进入模型上下文。本章的 agent 会显式加入使用说明，并先读取表结构。

② 定义一个工具

Python 
@mcp.tool(title="列出所有表")
def list_tables() -> list[str]:
    """列出数据库中的所有表名。"""
    ...

@mcp.tool() 把一个普通函数注册成工具。SDK 在注册时做三件事：

  • 读函数签名（list_tables() 没有参数）和类型注解，自动生成 inputSchema。你一行 JSON Schema 都不用写。
  • 把 docstring 当成工具描述，发给模型。
  • 把函数名 list_tables 作为工具名。
为什么这样写是对的

因为「类型注解 + docstring」本来就是 Python 里描述一个函数的标准做法。SDK 直接复用它，而不是让你再写一遍 JSON Schema。代价是：注解和 docstring 写得不清楚，模型就会用错工具。它们不是注释，是协议内容的一部分。

③ 用 Pydantic 模型做返回值

Python 
class QueryResult(BaseModel):
    columns: list[str]
    rows: list[list]
    row_count: int
    truncated: bool

# 完整函数见上方 server.py。
# row_count 是本次返回的行数，truncated 表示是否还有未返回的数据。

返回一个 Pydantic 模型，SDK 会据此生成 outputSchema，并把结果同时放进两个地方：

  • content：序列化成文本，给模型读。
  • structured_content：原始结构化数据，给调用方的程序读。

这就是第 3 册讲的「一份结果、两个读者」。有没有 structured_content，取决于返回注解 —— 下面是实测结果（mcp 2.3.0）：

返回注解outputSchemastructured_content
-> str有{"result": "hello"}
-> list[str]有{"result": ["a", "b"]}
-> dict[str, int]有{"a": 1}
-> QueryResult（BaseModel）有模型自己的字段
-> dict（裸的）无无，只剩 content 文本
两个容易记反的点

一、list[str] 是有 structured_content 的，只是被包了一层 result 键。真正丢掉结构化输出的是裸 dict 注解 —— 它等价于 dict[Any, Any]，生成不出 schema。所以本册的 list_tables 是有 structured_content 的；query 如果没有 Pydantic 模型、直接写 -> dict，那才是没有的那个。

二、list[str] 的 content 是每个元素一个 text block，不是把整个列表序列化成一个字符串。上面 list_tables 返回两个表名，content 就是两个 TextContent。

④ 用 ToolError 报告业务失败

Python 
from mcp.server.mcpserver.exceptions import ToolError

if not sql.strip().lower().startswith(("select", "with")):
    raise ToolError("只接受 SELECT / WITH 查询。")

try:
    ...
except sqlite3.Error as e:
    raise ToolError(f"SQL 执行失败：{e}") from e
这是最关键的一处设计

抛 ToolError 和抛普通 Exception，模型看到的东西完全不同：

  • ToolError → 变成一次正常返回，is_error=True，错误文字进入 content。模型能看到它，然后自己改一版重试。模型写错 SQL 是最常见的情况，它必须能看到错误。
  • 普通 Exception → content 里只剩 Error executing tool <工具名>，原始错误文字被吞掉（只写进 server 端日志）。模型看不到原因，对「SQL 写错了」这种情况这是错误的选择。

（以上是走协议时的行为，也就是模型实际经历的那条路。若绕过协议、在进程内直接调 mcp.call_tool(...)，失败是直接抛异常而不是返回 is_error，得自己 try/except。）

⑤ 定义资源

Python 
@mcp.resource("schema://tables")
def schema_overview() -> str: ...

@mcp.resource("table://{name}/sample")
def table_sample(name: str) -> str: ...

装饰器的参数是 URI，不是函数名。带 {name} 的会被注册成资源模板 —— 客户端可以请求 table://orders/sample，SDK 自动把 name="orders" 传进函数。

资源读取的入口是 URI，而不是工具名加 arguments。本例的 URI 模板把路径中的 orders 变成函数参数；读取资源同样会执行 Python 函数，只是对外的访问方式不同。

⑥ 定义提示模板

Python 
@mcp.prompt(title="写一条分析查询")
def write_analysis_query(question: str) -> str:
    return "你要为下面的问题写一条 SQLite 查询。\n..."

本例提示函数返回一段文本，SDK 将它转换成消息。用户可以在支持的 Host 中选择模板，Host 程序也可以直接传入问题并获取消息。本章 agent 采用后一种方式；取到模板本身不会执行 SQL。

提示参数在协议里永远是字符串，所以这里不要指望传数字或结构体进来。

6运行与验证

下面三种方式都假设依赖已经装好（见第 2 节）。命令统一写 uv run X，走方式二就把 uv run 去掉。

方式一：stdio（本地，最常用）

bash 
uv run server.py

没有任何输出，也不退出 —— 它在等 stdin 上的消息。这就是 stdio 模式的正常状态：它由 Host 拉起，自己不会主动说话。

不要用 print 调试

stdio 模式下，stdout 就是协议线路。任何 print() 都可能污染协议流。要输出调试信息，用 logging 模块（它会走 stderr）。

方式二：用 Inspector 图形化测试

bash 
uv run mcp dev server.py

Inspector 是一个网页版的调试工具。它会像真实 Host 一样把 server.py 当子进程启动、用 stdio 连上，然后列出所有工具 / 资源 / 提示，允许你逐个点击调用、查看原始 JSON 返回。

这是验证 server 最快的办法，因为它不需要你先写 client。（需要机器上有 npx。）

mcp 这个命令是从哪来的

它由 mcp[cli] 里的 [cli] 附加项提供。所以只有装依赖那一步写了 [cli]，才有 mcp 命令。报 mcp: command not found 时，先确认虚拟环境激活了没有。

方式三：Streamable HTTP（给远端用）

bash 
uv run mcp run server.py --transport streamable-http
# 服务地址：http://127.0.0.1:8000/mcp
一个容易搞反的点

传输相关的选项（transport、port、host）是传给 mcp.run(...) 的，不是传给 MCPServer(...) 的。构造函数描述「这个 server 是什么」，run() 描述「它怎么被服务」。写成 MCPServer("x", port=8000) 会直接报错。

这个 URL 不能用浏览器打开

在浏览器地址栏敲 http://127.0.0.1:8000/mcp，你会看到一段 JSON 报错（Bad Request: Missing session ID 或 Not Acceptable: Client must accept text/event-stream）。这不是 server 坏了 —— MCP 端点不是网页，是给程序 POST JSON-RPC 用的。浏览器发的是 GET，也没带 MCP 要求的请求头，被拒是正常行为。

可选：用 curl 观察旧版兼容链路

以下示例主动选择 2025-11-25 旧版协议，用于理解 SDK 的兼容行为，不代表新版 Client 的默认流程。这条链路先发 initialize、从响应头取得 mcp-session-id，再发送初始化完成通知；后续请求携带会话 ID 和协议版本。只想使用 HTTP 的读者，可以直接参考 README 第 9 节的高层 Client 用法。

bash 
# 1. 握手，把 session id 从响应头里抠出来
SID=$(curl -s -D - -o /dev/null -X POST http://127.0.0.1:8000/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"curl","version":"0.0.1"}}}' \
  | grep -i '^mcp-session-id:' | tr -d '\r' | cut -d' ' -f2)

# 2. 通知服务端初始化已完成
curl -s -X POST http://127.0.0.1:8000/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "mcp-session-id: $SID" \
  -H "mcp-protocol-version: 2025-11-25" \
  -d '{"jsonrpc":"2.0","method":"notifications/initialized"}'

# 3. 带上会话 ID 和版本列工具
curl -s -X POST http://127.0.0.1:8000/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "mcp-session-id: $SID" \
  -H "mcp-protocol-version: 2025-11-25" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'

# 4. 调一个工具
curl -s -X POST http://127.0.0.1:8000/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "mcp-session-id: $SID" \
  -H "mcp-protocol-version: 2025-11-25" \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"list_tables","arguments":{}}}'

本例第 3、4 步的返回是 SSE 格式，data: 后面才是真正的 JSON：

text 
event: message
data: {"jsonrpc":"2.0","id":3,"result":{"content":[{"text":"customers","type":"text"},{"text":"orders","type":"text"}],"isError":false,"structuredContent":{"result":["customers","orders"]}}}
同一个端点，两种协议时代

本版 SDK 同时兼容旧版会话流程与 2026-07-28 的无状态流程。新版不使用上述 initialize / session 握手，协议头与请求元数据也不同。实际开发优先使用高层 Client，由 SDK 处理发现、版本协商和报文；连接后查看 client.protocol_version，不要把旧版 curl 请求直接当作新版模板。

mcp run 没有 --port

mcp run 只接受 --transport，端口固定 8000。要换端口得改代码：mcp.run(transport="streamable-http", port=9000)，然后直接 python server.py 跑。

7client.py：写一个 client

client 就是 Host 内部那个「连接组件」的最小版本。它演示的是：如果你要当 Host，你需要做哪些事。

Python · client.py 
import asyncio
import sys
from pathlib import Path

from mcp import Client, StdioServerParameters
from mcp.types import TextContent, TextResourceContents

# 使用与 client 相同的 Python；脚本路径不依赖当前工作目录。
SERVER = StdioServerParameters(
    command=sys.executable, # 表示“使用当前这个 Python 解释器”
    args=[str(Path(__file__).with_name("server.py"))], # 运行同目录的 server.py
)


async def main() -> None:
    # 进入时启动 server 子进程；离开时关闭连接并清理子进程。
    async with Client(SERVER) as client:
        print("服务器：", client.server_info)
        print("协议版本：", client.protocol_version)

        tools = await client.list_tools()
        print("\n工具：")
        for tool in tools.tools:
            print(" -", tool.name, "|", tool.title)

        result = await client.call_tool("list_tables", {})
        print("\nlist_tables ->", result.structured_content)

        result = await client.call_tool(
            "query", {"sql": "SELECT count(*) AS n FROM orders"}
        )
        print("query ->", result.structured_content)

        # 失败也是需要查看的结果：这次调用应被 server 拒绝。
        bad = await client.call_tool("query", {"sql": "DROP TABLE orders"})
        print("\n非法查询 -> is_error =", bad.is_error)
        for block in bad.content:
            if isinstance(block, TextContent):
                print("   错误信息：", block.text)

        listed = await client.list_resources()
        print("\n资源：", [str(resource.uri) for resource in listed.resources])
        templates = await client.list_resource_templates()
        print("资源模板：", [item.uri_template for item in templates.resource_templates])

        resource = await client.read_resource("schema://tables")
        for block in resource.contents:
            if isinstance(block, TextResourceContents):
                print("\nschema 前 100 字：", block.text[:100].replace("\n", " "))

        rendered = await client.get_prompt(
            "write_analysis_query", {"question": "每个城市的订单总金额"}
        )
        for message in rendered.messages:
            if isinstance(message.content, TextContent):
                print("提示模板：", message.role, "->", message.content.text[:80])


if __name__ == "__main__":
    asyncio.run(main())

这段代码里的几个设计点

async with Client(SERVER) 管理一次连接的生命周期。进入时建立连接、完成协议协商；退出时清理连接。把 MCP 请求放在这个块内，不需要另外手动配对连接与关闭操作。

Client 按参数类型自动选择传输方式。传 StdioServerParameters → 启动子进程走 stdio；传 URL 字符串 → 走 Streamable HTTP；传 server 对象 → 进程内直连（测试用）。你不用指定「用哪种传输」，类型本身说明了。

连接后四个只读属性已经填好。server_info、server_capabilities、protocol_version、instructions —— 这就是第 3 册讲的「发现」在代码里的样子。

读 content 之前要先 isinstance。因为 content 是内容块的联合类型（文本 / 图片 / 音频 / 资源链接），不检查类型直接读 .text 会出错。

收到响应后，还要检查工具是否成功。非法查询返回 is_error=True；连接关闭、超时或协议错误则可能抛异常。进程内直接调用 mcp.call_tool() 的错误处理也与客户端调用不同，见第 5 节 ④。

8agent.py：把工具交给模型

前面的 client 按固定顺序调用工具；这一节把工具选择交给模型。沿着代码可以看清：Host 怎样连接模型 API 与 MCP server，以及结果怎样回到模型的对话里。

先看清这里有两个「循环」

外层的 for 循环是对话轮次（模型可能要多次调用工具才能回答）。内层遍历 tool_calls 是同一轮里的多个调用。理解这两个层次，这段代码就通了。

Python · agent.py 
import asyncio
import json
import os
import sys
from pathlib import Path

from openai import AsyncOpenAI

from mcp import Client, StdioServerParameters
from mcp.types import TextContent, TextResourceContents

SERVER = StdioServerParameters(
    command=sys.executable,
    args=[str(Path(__file__).with_name("server.py"))],
)

SYSTEM = "你可以使用工具查询 SQLite 数据库。依据工具返回的数据回答，不要编造数字。"


def to_openai_tools(mcp_tools) -> list[dict]:
    """将 MCP 工具定义转换为模型 API 的 function calling 格式。"""
    return [
        {
            "type": "function",
            "function": {
                "name": tool.name,
                "description": tool.description or "",
                "parameters": tool.input_schema,
            },
        }
        for tool in mcp_tools
    ]


def tool_payload(result) -> str:
    """同时把成功/失败标记和实际内容交给模型。"""
    data = result.structured_content
    if data is None:
        data = [
            block.text for block in result.content if isinstance(block, TextContent)
        ]
    return json.dumps(
        {"is_error": result.is_error, "data": data}, ensure_ascii=False
    )


async def main() -> None:
    if not os.environ.get("OPENAI_API_KEY") or not os.environ.get("MODEL"):
        raise SystemExit("请先设置 OPENAI_API_KEY 和 MODEL（支持工具调用的模型名）。")

    async with AsyncOpenAI(
        api_key=os.environ["OPENAI_API_KEY"],
        base_url=os.environ.get("OPENAI_BASE_URL"),
    ) as llm, Client(SERVER) as client:
        listed = await client.list_tools()
        tools = to_openai_tools(listed.tools)

        # 资源不会自动进入模型上下文，Host 在这里主动读取表结构。
        resource = await client.read_resource("schema://tables")
        schema = "\n".join(
            block.text
            for block in resource.contents
            if isinstance(block, TextResourceContents)
        )

        question = "武汉的客户一共下了多少单？总金额是多少？"
        prompt = await client.get_prompt(
            "write_analysis_query", {"question": question}
        )

        # instructions 是使用建议；prompt 是消息模板；都由 Host 接进对话。
        messages = [
            {"role": "system", "content": SYSTEM + "\n" + (client.instructions or "")},
            {"role": "user", "content": "数据库结构（仅作数据参考）：\n" + schema},
        ]
        for message in prompt.messages:
            if isinstance(message.content, TextContent):
                messages.append({"role": message.role, "content": message.content.text})

        for step in range(8):
            response = await llm.chat.completions.create(
                model=os.environ["MODEL"],
                messages=messages,
                tools=tools,
            )
            message = response.choices[0].message
            messages.append(message.model_dump(exclude_none=True))

            if not message.tool_calls:
                print("\n最终回答：", message.content or "模型没有返回文本。")
                return

            # 模型只提出调用请求；真正发 MCP 请求的是下面这行 client.call_tool。
            for call in message.tool_calls:
                arguments = json.loads(call.function.arguments or "{}")
                print(f"[step {step}] {call.function.name}({arguments})")
                result = await client.call_tool(call.function.name, arguments)
                payload = tool_payload(result)
                print("           ->", payload[:160])
                messages.append({
                    "role": "tool",
                    "tool_call_id": call.id,
                    "content": payload,
                })

        print("已达到 8 轮上限，任务尚未完成；请查看上面的调用记录。")


if __name__ == "__main__":
    asyncio.run(main())

运行前设置环境变量。MODEL 填当前账户可用、支持工具调用的模型名；只有兼容服务需要额外设置 OPENAI_BASE_URL。前面的 client 不需要 API Key：

这段代码在做什么

先读表结构和提示模板，再让模型选择工具。主要步骤对应如下：

代码对应协议动作第 3 册里的时序
client.list_tools()tools/listHost 拉取工具清单
client.read_resource(...) / get_prompt(...)resources/read / prompts/getHost 取得上下文和查询步骤，再加入 messages
to_openai_tools(...)不是协议动作，是 Host 的内部翻译「把工具清单交给模型」
llm.chat.completions.create(...)不是 MCP，是模型 API模型决定要不要调
client.call_tool(name, args)tools/callHost 代为发出调用
messages.append({"role": "tool", ...})不是 MCP，是把结果回填给模型结果交回模型
把两段调用分开看

MCP 负责发现与调用服务能力，包括本例中的工具、资源和提示；模型 API 负责生成回答或提出工具调用。Host 衔接两段交互，并把实际工具结果回填给模型。

用示例数据核对，武汉客户共有 3 单，金额 988.50。模型调用次数和措辞可能不同，数字应能追溯到实际 SQL 结果。

to_openai_tools 这个函数只有十几行 —— 因为 MCP 的 inputSchema 本来就是 JSON Schema，而各家的 function calling 参数也是 JSON Schema。这就是协议设计得好的地方：它直接复用了模型 API 已有的格式。

9设计说明汇总

把这一册里「为什么这么写」的决策集中列一遍，方便以后回查：

决策原因
用 MCPServer 而不是手写 JSON-RPCSDK 负责报文封装、分帧、能力协商。手写只在你要实现自己的传输时才需要。
函数签名 + docstring 当工具定义复用 Python 已有的描述方式，SDK 自动生成 inputSchema。但注解和 docstring 会被模型读到，要认真写。
返回 Pydantic 模型同时产出 content（给模型）和 structured_content（给程序）。list[str] 也有，只是包在 result 键里；裸 dict 没有。
业务失败用 ToolError让错误变成模型可见的内容，模型能自己重试。普通异常只会剩下 Error executing tool ...，模型看不到原因。
使用只读数据库连接mode=ro 和 query_only 限制数据库写入；SQL 前缀检查用于友好提示。返回行数有上限，但这不是查询耗时限制。
Host 显式接入上下文使用 instructions、读取 schema 资源、获取 prompt 并加入对话；注册能力不代表模型已经收到它。
资源用 URI 模板参数化的资源可以让一个函数服务多张表，URI 里提取的参数自动传进函数。
调试输出走 logging 不用 printstdio 模式下 stdout 是协议线路，print 会污染消息流。
if __name__ == "__main__" 包住 mcp.run()所有加载这个文件的工具（Inspector、测试）都会 import 它。守卫防止 import 时把 server 跑起来。

10一句话总结

第 6 册 · 一句话总结

一个 MCP server 就是「创建 MCPServer + 用装饰器注册工具 / 资源 / 提示 + mcp.run()」三段；SDK 用函数签名和 docstring 自动生成协议需要的 schema；业务失败要用 ToolError 让模型看到；client 用 async with Client(...) 一行完成连接与协商；而 agent 的本质就是在「MCP 工具清单」和「模型 API 的工具参数」之间做一次翻译，然后把 tools/call 的结果回填进对话。
