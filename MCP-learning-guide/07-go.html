用 Go 写一个文件系统 MCP

用熟悉的 Go 代码接入 MCP：实现列目录和读取文本，再看清工具注册、协议会话与结果返回。

第 7 册 · Go 1.25+ · 官方 go-sdk v1.8.0 · 示例采用 stdio
这一册的成果

完成后，客户端可以读取一个指定目录中的 UTF-8 文本，并在路径越界或文件过大时收到明确错误。整个示例不需要数据库，也不需要模型 API Key。第 6 册学习查数据，这次练习处理真实文件。

本章面向有 Go 编程基础、第一次使用 MCP / MCP SDK 的开发者。重点是 SDK 如何把普通函数暴露为工具，以及 Client 如何发现、调用并取得结果；泛型处理函数、上下文和生命周期会结合示例简要说明。

1这次做什么

工具输入输出
list_directory{"path":"."}目录条目，以及结果是否被截断
read_text_file{"path":"hello.txt"}文件相对路径和文本内容

. 表示配置的根目录；notes/guide.md 表示根目录下 notes 文件夹中的文件。服务只提供读取能力，不提供写入、删除或执行文件。读文件最多 64 KiB，列目录最多返回 100 个条目。

这里的“根目录”是谁决定的？

由启动 server 的人通过 -root 参数指定，例如 ./workspace。它不是电脑磁盘根目录，也不由模型随意选择。os.Root 用于限制文件访问范围；它不等于运行任意程序的沙箱。

2准备目录和依赖

先安装 Go 1.25 或更新版本，运行 go version 确认。接着在一个新目录中执行：

终端 
mkdir mcp-demo-go
cd mcp-demo-go
go mod init example.com/mcp-demo-go
go get github.com/modelcontextprotocol/go-sdk/mcp@v1.8.0
mkdir server
mkdir client
mkdir workspace

go mod init 给项目建立依赖清单，go get 下载指定版本的 SDK。这个示例没有 SQLite 驱动，文件操作来自 Go 标准库。

mcp-demo-go/ ├── go.mod ├── go.sum ├── server/ │ └── main.go # 下一节的服务端代码 ├── client/ │ └── main.go # 第 4 节的客户端代码 └── workspace/ └── hello.txt # 手动创建一个 UTF-8 文本文件

用编辑器创建 workspace/hello.txt，保存为 UTF-8，写入下面这行文字：

hello.txt 
Hello, MCP!

server 和 client 各自有一个 main() 入口，所以放进两个子目录。后面 go build ./server 构建服务端，go run ./client 运行客户端。

已有项目怎么办？

不要在已有目录重复执行 go mod init。初次学习建议使用新的 mcp-demo-go 目录，以免和 Python 示例混在一起。依赖下载失败时先检查网络与本机 Go 代理配置，不必为教程永久修改全局设置。

3写服务端：server/main.go

把下面代码完整保存到 server/main.go。先浏览四个部分即可：输入输出类型、路径打开函数、两个工具、启动服务。暂时不熟悉的签名可以等到第 6 节再看。

Go · server/main.go 
package main

import (
	"context"
	"flag"
	"fmt"
	"io"
	"log"
	"os"
	"path/filepath"
	"sort"
	"strings"
	"unicode/utf8"

	"github.com/modelcontextprotocol/go-sdk/mcp"
)

const maxFileBytes = 64 * 1024
const maxEntries = 100

// JSON 字段名是客户端实际发送的名字。
type PathInput struct {
	Path string `json:"path" jsonschema:"Path relative to the configured root; use . for its top directory"`
}

type Entry struct {
	Name  string `json:"name"`
	IsDir bool   `json:"is_dir"`
}

type DirectoryResult struct {
	Entries   []Entry `json:"entries"`
	Truncated bool    `json:"truncated"`
}

type FileResult struct {
	Path string `json:"path"`
	Text string `json:"text"`
}

// 所有打开操作都经过 os.Root，而不是只做字符串前缀判断。
func openLocal(root *os.Root, name string) (*os.File, error) {
	if !filepath.IsLocal(name) {
		return nil, fmt.Errorf("请使用根目录内的相对路径，例如 . 或 notes/hello.txt")
	}
	file, err := root.Open(name)
	if err != nil {
		return nil, fmt.Errorf("无法打开 %q；请检查路径、权限和根目录范围", name)
	}
	return file, nil
}

func main() {
	rootPath := flag.String("root", "./workspace", "Directory available to this server")
	flag.Parse()

	root, err := os.OpenRoot(*rootPath)
	if err != nil {
		log.Fatal("无法打开根目录：", err)
	}
	defer root.Close()

	server := mcp.NewServer(
		&mcp.Implementation{Name: "filesystem-demo", Version: "0.1.0"},
		&mcp.ServerOptions{
			Instructions: "先列目录，再读取需要的文本。所有路径相对于配置的根目录；此服务不提供写入或删除。",
		},
	)

	mcp.AddTool(server, &mcp.Tool{
		Name:        "list_directory",
		Description: "列出指定目录的至多 100 个条目。path 为根目录内相对路径，. 表示根目录。",
	}, func(ctx context.Context, req *mcp.CallToolRequest, input PathInput) (*mcp.CallToolResult, DirectoryResult, error) {
		file, err := openLocal(root, input.Path)
		if err != nil {
			return nil, DirectoryResult{}, err
		}
		defer file.Close()

		items, err := file.ReadDir(maxEntries + 1)
		if err != nil && err != io.EOF {
			return nil, DirectoryResult{}, fmt.Errorf("无法列目录：请确认 %q 是目录", input.Path)
		}
		truncated := len(items) > maxEntries
		if truncated {
			items = items[:maxEntries]
		}
		sort.Slice(items, func(i, j int) bool { return items[i].Name() < items[j].Name() })

		entries := make([]Entry, 0, len(items))
		for _, item := range items {
			entries = append(entries, Entry{Name: item.Name(), IsDir: item.IsDir()})
		}
		return nil, DirectoryResult{Entries: entries, Truncated: truncated}, nil
	})

	mcp.AddTool(server, &mcp.Tool{
		Name:        "read_text_file",
		Description: "读取根目录内不超过 64 KiB 的 UTF-8 文本文件；不接受目录、过大文件或含 NUL 的内容。",
	}, func(ctx context.Context, req *mcp.CallToolRequest, input PathInput) (*mcp.CallToolResult, FileResult, error) {
		file, err := openLocal(root, input.Path)
		if err != nil {
			return nil, FileResult{}, err
		}
		defer file.Close()

		info, err := file.Stat()
		if err != nil || !info.Mode().IsRegular() {
			return nil, FileResult{}, fmt.Errorf("请提供普通文本文件的路径")
		}
		data, err := io.ReadAll(io.LimitReader(file, maxFileBytes+1))
		if err != nil {
			return nil, FileResult{}, fmt.Errorf("读取 %q 失败", input.Path)
		}
		if len(data) > maxFileBytes {
			return nil, FileResult{}, fmt.Errorf("文件超过 64 KiB，请选择较小的文本文件")
		}
		if !utf8.Valid(data) || strings.ContainsRune(string(data), '\x00') {
			return nil, FileResult{}, fmt.Errorf("文件不是本示例支持的 UTF-8 文本")
		}
		return nil, FileResult{Path: input.Path, Text: string(data)}, nil
	})

	// log 默认写 stderr；stdout 留给 MCP 报文。
	log.Printf("filesystem-demo 已启动，根目录：%s", *rootPath)
	if err := server.Run(context.Background(), &mcp.StdioTransport{}); err != nil {
		log.Fatal(err)
	}
}

这里的两次 mcp.AddTool 是注册。只有客户端发起调用，SDK 才会执行对应的处理函数。server.Run 则负责持续接收和处理请求。

路径检查为什么有两层？

filepath.IsLocal 先拒绝绝对路径和词法上越界的路径，帮助给出清楚的提示；真正打开文件使用 root.Open，避免目录中的符号链接把读取带到根目录以外。仅用字符串判断“路径以 workspace 开头”并不可靠。

这是限定目录读取的学习示例。操作系统权限、挂载点等仍属于运行环境的边界，不能由一个路径字符串检查全部解决。

4写验证客户端：client/main.go

这个客户端会启动服务端，然后做三件事：列目录、读取 hello.txt、尝试越界读取。前两次应该成功，第三次应该失败。

Go · client/main.go 
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"os"
	"os/exec"
	"path/filepath"
	"time"

	"github.com/modelcontextprotocol/go-sdk/mcp"
)

func run() error {
	if len(os.Args) != 3 {
		return fmt.Errorf("用法：go run ./client <server 可执行文件> <允许访问的目录>")
	}
	serverPath, err := filepath.Abs(os.Args[1])
	if err != nil {
		return err
	}
	rootPath, err := filepath.Abs(os.Args[2])
	if err != nil {
		return err
	}

	ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
	defer cancel()

	client := mcp.NewClient(
		&mcp.Implementation{Name: "filesystem-client", Version: "0.1.0"},
		nil,
	)
	command := exec.Command(serverPath, "-root", rootPath)
	command.Stderr = os.Stderr
	session, err := client.Connect(ctx, &mcp.CommandTransport{Command: command}, nil)
	if err != nil {
		return err
	}
	defer session.Close()

	listed, err := session.ListTools(ctx, nil)
	if err != nil {
		return err
	}
	for _, tool := range listed.Tools {
		fmt.Println("工具：", tool.Name)
	}

	// 先列目录，再读文件，最后验证越界路径会被拒绝。
	cases := []struct {
		name string
		path string
	}{
		{"list_directory", "."},
		{"read_text_file", "hello.txt"},
		{"read_text_file", "../outside.txt"},
	}
	for _, item := range cases {
		result, err := session.CallTool(ctx, &mcp.CallToolParams{
			Name:      item.name,
			Arguments: map[string]any{"path": item.path},
		})
		if err != nil {
			return fmt.Errorf("MCP 请求失败：%w", err)
		}
		fmt.Printf("\n%s(%q) is_error=%v\n", item.name, item.path, result.IsError)
		if result.IsError {
			for _, block := range result.Content {
				if text, ok := block.(*mcp.TextContent); ok {
					fmt.Println(text.Text)
				}
			}
			continue
		}
		data, err := json.MarshalIndent(result.StructuredContent, "", "  ")
		if err != nil {
			return err
		}
		fmt.Println(string(data))
	}
	return nil
}

func main() {
	if err := run(); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
}

CommandTransport 启动指定程序，并把标准输入、标准输出接成 MCP 通道；client.Connect 建立协议会话，返回的 session 用于后续请求；session.Close() 负责关闭这条会话。业务代码不需要自己拼报文或管理消息分帧。

5运行并核对结果

以下命令都在 mcp-demo-go 项目根目录执行。先编译 server，再让 client 启动编译好的程序。

Windows PowerShell 
go build -o filesystem-server.exe ./server
go run ./client ./filesystem-server.exe ./workspace
macOS / Linux 
go build -o filesystem-server ./server
go run ./client ./filesystem-server ./workspace

不用另外启动 server。客户端会完成这一步。输出中会看到两个工具名，然后出现类似结果：

关键输出（文件结尾换行可能不同） 
list_directory(".") is_error=false
{
  "entries": [{"name": "hello.txt", "is_dir": false}],
  "truncated": false
}

read_text_file("hello.txt") is_error=false
{
  "path": "hello.txt",
  "text": "Hello, MCP!"
}

read_text_file("../outside.txt") is_error=true
请使用根目录内的相对路径，例如 . 或 notes/hello.txt

如果 hello.txt 最后有换行，JSON 中的 text 会多一个 \n，不影响正确性。目录中有其他文件时，列表也会更多。目录超过 100 个条目时，返回读取到的一批条目并标记 truncated=true；本例没有实现分页。

第三次调用是特意设计的失败用例。它证明工具拒绝了越界路径，而不是 client 没连上。outside.txt 不需要真的存在。

6读懂 Go SDK 的写法

先看输入：结构体就是参数说明

Go · 代码摘录 
type PathInput struct {
    Path string `json:"path" jsonschema:"Path relative to the configured root; use . for its top directory"`
}

这里关注的是 SDK 如何生成工具定义：输入结构体决定参数结构，json 标签决定对外字段名，jsonschema 标签补充参数说明。客户端通过 tools/list 取得这些信息，调用时提交 {"path":"hello.txt"}；SDK 校验并解码后，处理函数才收到 PathInput。

再看处理函数：三个输入、三个返回值

Go · 签名示意 
func(
    ctx context.Context,
    req *mcp.CallToolRequest,
    input PathInput,
) (*mcp.CallToolResult, FileResult, error)
位置在这里的作用
ctx携带取消、超时等执行上下文；本例的本地文件读取没有额外使用它
req完整 MCP 调用信息；暂时不用，可以先不展开
inputSDK 解码并检查后的业务参数，读取 input.Path 即可
第一个返回值自定义 MCP 结果。本例返回 nil，交给 SDK 生成
第二个返回值业务结果，如 FileResult{Path: ..., Text: ...}
第三个返回值nil 表示成功；普通 error 在此高层注册方式下转换成工具错误

因此成功时的 return nil, FileResult{...}, nil 可以读成：“不用自定义报文；业务结果在这里；没有错误。”失败时的 return nil, FileResult{}, err 则是：“没有可用业务结果；错误原因在这里。”

本例使用的是泛型函数 mcp.AddTool，SDK 会自动转换结果、处理工具错误。不要把它与更底层的 server.AddTool 混淆；后者的参数和错误处理约定不同。

这里没有显式写泛型实参，因为 Go 会从处理函数签名推导输入和输出类型；SDK 再据此生成输入、输出 Schema。修改 PathInput 或 FileResult，不只是修改内部类型，也是在修改客户端看到的工具接口。

共享依赖与服务生命周期

两个处理函数复用启动时打开的 root，服务退出时再统一关闭。MCP 不规定业务代码必须放在闭包里：后续可以提取独立 handler，或通过结构体注入依赖，只要保持工具定义与处理函数的输入输出一致。

7一次读文件的完整来回

client 调用 read_text_file，参数 path="hello.txt" ↓ Client SDK 生成 tools/call 请求，通过 stdio 发送 ↓ Server SDK 找到 read_text_file 并检查输入结构 ↓ 处理函数通过 root.Open 打开文件，检查类型与大小，读取文本 ↓ 返回 FileResult{Path: "hello.txt", Text: "Hello, MCP!"} ↓ Server SDK 生成 MCP 响应 ↓ Client SDK 解码 → result.StructuredContent → 打印 JSON

这条链路没有调用大模型。接入 AI 应用后，变化发生在前面：由模型决定调用哪个工具、给什么参数，Host 再用 MCP Client 执行。服务端依然只处理明确的工具请求。

session.CallTool 有两层需要检查：返回的 err 代表请求层失败；拿到结果后，还要看 result.IsError 判断工具是否执行成功。

8接入现成的 Host

将编译好的可执行文件配置为本地 MCP server。下面是常见 JSON 配置形状；不同 Host 的入口和字段可能不同，应以它的配置说明为准。

Windows · 配置示例 
{
  "mcpServers": {
    "filesystem-demo": {
      "command": "C:/projects/mcp-demo-go/filesystem-server.exe",
      "args": ["-root", "C:/projects/mcp-demo-go/workspace"]
    }
  }
}

把两个路径替换为本机的绝对路径。Windows 的 JSON 可以使用正斜杠，避免反斜杠转义问题；macOS/Linux 则使用对应的可执行文件和目录绝对路径。

连接成功后，可以让助手：“列出允许目录中的文件，再读取 hello.txt，告诉我里面写了什么。”在 Host 中查看工具调用记录，应先看到 list_directory，再看到 read_text_file。如果服务已连接但模型没有调用，检查提示和 Host 的工具启用状态。

修改 Go 代码后要重新执行 go build，再重启 Host 中的 server。Host 启动的是编译后的文件，不会自动读取新的源码。

9扩展与练习

可以用三个小练习验证对 SDK 的理解：

  1. 在 workspace 中创建 notes/guide.md，用 path="notes/guide.md" 读取，确认路径以配置根目录为起点。
  2. 新增 file_info 工具，只返回文件大小和修改时间。复用 PathInput，但定义新的输出结构体。
  3. 分别读取不存在的文件、目录、超过 64 KiB 的文件，观察错误是否清楚，客户端是否仍能继续调用。

这个 server 只实现 Tools 就已经是一个可用的 MCP server；不需要为了“凑齐三种原语”再添加 Resource 和 Prompt。如果以后想按 URI 暴露固定的项目说明，再考虑资源；需要复用对话步骤时，再考虑提示模板。

10排错与参考

现象检查方法
找不到 Go 或版本过低先运行 go version；本教程固定的 SDK 需要 Go 1.25+
找不到 server 可执行文件先执行 go build；Windows 注意 .exe 后缀
无法打开根目录确认 workspace 已创建，并检查 client 最后一个参数（允许访问的目录）
hello.txt 读取失败确认文件放在指定的 workspace 内，保存为 UTF-8
独立启动 server 后一直等待stdio 服务正在等请求；使用 client 或 Host 连接
JSON 解析报错不要在 server 中用 fmt.Println 输出调试内容；使用 log 写 stderr
工具列表没有更新重新编译 server，再重启它

核对接口时可参考 官方 Go SDK v1.8.0、mcp 包参考和 os.Root 文档。本章示例围绕目录和普通文本文件展开，扩展到大文件、分页或写入时，需要重新设计接口与边界。

把这三个动作记下来

用结构体描述输入输出，用 mcp.AddTool 注册处理函数，用 server.Run 接收请求。文件怎么读由你写，MCP 消息怎么收发由 SDK 处理。
